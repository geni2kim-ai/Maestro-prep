# 로컬 노드 전달용 설치·통합 시험 프롬프트 (비공개 채널에서만 사용)

작업 범위는 제공된 `maestro-prep` 후보 폴더의 읽기·검증과 격리된 로컬 통합 시험이다. 전체 코드베이스, 로컬 로그, 실제 시스템 경로, 자격증명 또는 비밀 아이디어를 외부 챗봇으로 송신하지 않는다. 현행 사용자 지시와 노드 정책이 이 요청보다 우선한다.

1. 패키지 ZIP의 신뢰 가능한 외부 SHA-256을 대조하고 별도 작업 디렉터리에 압축 해제한다. 기존 Astra-Prep 승인본이나 Leonardo 라우터 설치본을 덮어쓰지 않는다.
2. `tools/verify_package.py`, `component-check`, 공통 진입점 테스트, vendored O-Prep 61개 회귀, `tools/replay_simulation.py`를 수행해 실제 stdout/exit와 실행 시각, 실행자, 패키지 SHA를 자기 로컬 보관소에 기록한다. 시험 실패 시 임의로 정책을 바꾸거나 우회하지 않는다.
3. 자기 노드의 승인된 Astra-Prep 실제 SKILL.md 및 Leonardo 바이너리/정책의 정확한 버전·바이트 해시를 조회한다. 현재 스키마/입출력과 이 후보의 `adapters/` 사이를 diff하되 공식 도구 실행이 불가하면 `NOT_RUN`으로 기록한다.
4. 현행 승인된 Leonardo로 *권한상 허용된 무해한 샘플*의 라우팅을 별도 수행할 수 있는 경우 개인 증거 루트에 입력·정책·출력과 메타데이터만 바이트 결합한다. 승인된 Astra-Prep에서 생성한 계획 영수증을 동일한 작업 식별자로 분리 보관한다.
5. `decide`를 `NEW_PLAN`, `REUSE_PLAN`, `READ_ONLY`, `PUBLISH/CLOSE`로 각각 시험하고, 필수 O-Prep 실행이 누락되지 않았는지, Astra 누락 시 적절히 보류/감사 분리가 되는지, stale hash/잘못된 리뷰/ACK 누락 시 실패 안전한지 확인한다. 단순 모델이 PASS라고 대답했다는 이유로 승인·채택하지 않는다.
6. 운영/공유/Live 설치·원격 패킷 발행·승인 변경은 **하지 않는다**. 적용 필요 시 정확한 diff, 테스트 영수증, rollback, 별도 독립 검토, 정책 소유자·사용자 승인을 요청한다.

**반환 형식:** 외부 공유용에는 작업 ID, 후보 패키지 SHA, 20개 합성 결과, 실제 로컬 테스트/NOT_RUN 구분, 스킬/라우터 공식 버전(필요하면 내부 식별자 비공개), 어댑터 호환성 문제 코드, 미해결 게이트와 다음 허용 작업만 넣는다. 내부 보관용 원본 ZIP/로그/코드 전문은 외부에 제공하지 않는다.
